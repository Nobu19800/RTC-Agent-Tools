# 新規モジュールの実装とビルド

- アルゴリズム、座標変換、画像処理、計画、入力検証は独立したコアに置く。コアは OpenRTM、CORBA、IDL 型に依存せず、言語標準のデータ型を使う。
- ポート登録、読み書き、型変換、設定バインディング、サービス呼び出し、状態遷移は Builder が生成した RTC ファイルに置く。
- 実行時の入出力・設定・プロセス管理に JSON を用いない。設計・プロファイルと検証記録の JSON はツール用として扱う。既存の例外と移行状況は明記する。
- 必要なら共有 IDL を作り、接続先全体で同一の定義とハッシュを使う。標準 IDL のシンボルを重複コンパイルしない。型の単位、座標系、有効条件を明記する。
- GUI 制御では入力解除、タイムアウト、状態の鮮度、通信断、停止の条件を定義し、コマンドを送らないことと、進行中の動作の停止を分けて扱う。
- C++ はコアのソース・ヘッダーを追加し、ライブラリと実行ファイル双方の CMake ターゲットに含める。Python と Lua はコアを別モジュールに置き、使用するインタープリターと配布パスで解決できるようにする。
- 実装済みスケルトンを上書きしない。承認後の型や設定の変更は、設計、プロファイル、IDL、コード、ビルドと実行設定に反映し、旧型の接続を再作成する。

対象言語の環境と依存関係を確認し、指定したソースで構成・ビルドする。既存 RTC は取得時のソースでビルドし、変更が必要な場合は理由と作業範囲を明示する。ビルド・リンク・パッケージ化の成否を記録する。明示依頼があった場合だけ [静的解析と単体テスト](module-checks.md) を実行する。動作確認とログは [検証手順](verification.md) に従う。
