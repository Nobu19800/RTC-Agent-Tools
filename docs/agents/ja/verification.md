# 検証とログの確認

検証はユーザーが依頼した範囲で行う。ビルド・単体テスト・接続・転送・画面・実機動作は結果を別々に示す。静的解析と単体テストは [依頼時の検証手順](module-checks.md) に従う。

- 実行ごとに固有のログを用意し、確定設計のハッシュ、コード・設定・依存の版、実行コマンド、PID、時刻とタイムゾーン、結果を記録する。古いログやスキップした項目を現在の検証結果として扱わない。
- 終了後に標準出力、標準エラー、RTC・Manager・バッチのログを読み直す。発生した警告・エラーは原因、影響、対処と残作業を記録する。手動リトライの成功だけで永続修正と判断しない。
- システム実行前に権限を取得して GUI を操作する検証は、ユーザーが明示的に指示した場合に限り、権限を要求して実施する。構築・実行・動作確認のみの依頼では、利用できる CLI、API、ログ、データ転送で事前確認する。実行が依頼されており、事前確認で起動を妨げる問題がなければ、GUI の確認を待たずにシステムを起動する。起動後は、開く画面または URL、操作手順、期待する表示・動作、未確認の項目をユーザーに案内する。
- 許可された検証の範囲で GUI が要件なら WebSocket 接続のほか、必要なモデルと設定、ブラウザ例外、デコード済み状態、描画された場面を確認する。ヘッドレスと利用者のブラウザは検証範囲を分ける。
- 制御では入力解除、通信断、状態の鮮度、タイムアウトと各軸の実データを確認する。コマンドの停止と実動作の停止を区別する。
- 混在通信はシリアライザーのテスト、コネクタ確認、PDU やメッセージの実転送を分けて記録する。箱庭のロボット、チャンネル、容量とバイト配置、型変換を照合する。
- ライフサイクルは実行したコマンドと観測した状態を明示し、停止時には登録解除と所有プロセス終了を分けて確認する。
- 過去の証跡を保管し、今回の指紋に合う試験の結果から検証インデックスを更新する。テレオペの例では `scripts/verification_evidence.py`、`scripts/index_verification.py`、`scripts/finalize_gui_drone.py` を参照する。
