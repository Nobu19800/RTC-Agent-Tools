# Environment and dependency checks

Part of the mandatory instructions routed by [AGENTS.md](../../AGENTS.md).
Run read-only prerequisite checks before generation, installation or deployment. Report missing items and complete authorized setup; do not substitute an unrelated local checkout without recording its identity and compatibility.

- Resolve the actual Java executable and run a bounded version probe. Check Builder JARs and SDK plugin directories for required classes, not just directory existence. A PATH shim can exist while its Java invocation hangs. Record the selected JDK, Builder/library versions and generation command.
- Resolve the actual Python interpreter and verify imports in that interpreter: OpenRTM, omniORB, generated IDL, rtshell, and native `hakopy`/PDU converters when required. Record Python version/ABI, Foundation revision/build limits and native library search paths. A system Python import does not prove a virtual environment works. Inspect installed command help before choosing rtshell package names or flags.
- Check WSL distribution, GUI/display availability, filesystem paths and host boundaries. Keep machine-specific roots and browser executables in explicit arguments/environment settings. Do not assume Windows and WSL share native memory or Python installations.
- For WSL2 RTC deployment without an explicitly specified endpoint address, resolve an IP reachable from Windows and apply the [runtime endpoint rules](runtime.md). Check the current network configuration and distinguish RTC IOR publication from NameService access; retain explicit user/deployment addresses. Record unavailable Windows-side checks as unverified.
- Apply the same selected Windows-reachable WSL2 IP to NameService publication when its address is unspecified (default port 2809). Check both NameService and RTC advertised IORs from Windows; local health or TCP connectivity alone is insufficient. Reuse a compliant shared service, preserving explicit addresses and registration data during any necessary recovery.
- Include native parameter/configuration directories, plugins, model files, viewer submodules and generated JavaScript codecs in the dependency inventory. Check required revisions and layouts; an HTML response is insufficient. Fetch the parent-pinned submodule revision where available. If it is unavailable, record the explicitly selected revision and compatible verification scope instead of claiming parent compatibility.
- Dependency setup must be reproducible from a recorded source/revision or a supplied local artifact. Avoid hard-coded paths into a different Recipe's deployed output. Make dependency source and expected revision explicit, fail on mismatch/dirty source, and record deployed hashes. Do not run dependency install scripts without inspecting them.
- Preserve original files before deployment adjustments. Keep offline provenance/verification metadata separate from runtime settings. Configuration required by an upstream native API may retain JSON under the existing exception; do not extend JSON into generated RTC payloads or process manifests.

Use a reusable prerequisite checker where practical. Checks must fail clearly with the missing dependency and resolved path; they must not launch or activate the simulated system just to inspect availability. A generation/setup check is not runtime verification.

`scripts/preflight_environment.py` implements bounded Java/JAR checks, imports in the current interpreter (`--teleop`), and required viewer files (`--viewer-root`). Select checks explicitly; run Java checks on its host and native Python checks inside the selected Foundation. Supply `--output <evidence-path>` to retain the result. Runtime imports, source revision checks and browser execution remain distinct checks.

The sample viewer deployment accepts `--dependency-source <clean-checkout> --dependency-revision <full-commit>`; both are required. The browser check accepts `PLAYWRIGHT_MODULE`, `VIEWER_BROWSER_EXECUTABLE`, `VERIFY_PYTHON` and optional `VIEWER_URL`. The checker captures a unique image but leaves scene image review pending until the image is inspected. Do not report the user's in-app browser/GPU verified from this headless check.
